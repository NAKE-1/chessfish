Chessfish

Stockfish runs on the gaming PC. A small chess website runs in Docker on the Proxmox VM. A friend outside your tailnet plays on that website through a Tailscale share, and the gaming PC shows every statistic about the game.

How it fits together

The gaming PC always dials out to the container, so the container never needs a way back in. The friend's browser only ever talks to the container. The container also holds the rules, so a dropped PC or a tampered browser cannot corrupt the game.

A session, start to finish

  1. Install and pair onceRun ChessfishSetup.exe on the gaming PC. Its wizard picks a Stockfish build, enters the server address and generates a 32-byte pairing key, which you paste into the container's .env. The key itself never travels over the wire.
  2. Pick the gameIn the GUI you choose the mode (friend vs Stockfish, or friend vs you), your colour, the time control and the engine Elo. Meanwhile your friend has entered a display name and sees "Waiting for game".
  3. HandshakeThe PC sends HELLO with a fresh ephemeral X25519 key, a timestamp and a nonce, signed with the pairing key. The server answers WELCOME the same way. Each side derives one-off session keys and throws the ephemeral keys away afterwards.
  4. Encrypted startup packetThe first sealed frame is START, built on the spot from your settings: the session id, resume token, mode, clocks, engine settings, heartbeat timings and grace period. The server acknowledges it and the friend's page starts a countdown, then shows the board.
  5. PlayEvery move goes to the server, and python-chess checks it before anything changes. In engine mode Stockfish's reply comes from the PC after a human-like think time. In human mode you move on the Chessfish board. Either way the friend sees the same "Opponent", and your PC analyses throughout.
  6. HeartbeatEach side sends a PING every 2 s. RTT, jitter and loss are logged for both legs (PC to server and server to friend).
  7. End or adjournMate, resignation, a draw or a flag fall ends the game. The PGN, annotated with evals, move grades and clock times, is saved on your PC. The server keeps nothing.

Drop-outs

Clocks run on the server, so a lost link pauses the game instead of costing either player time.

okno pong 5 s → degraded8 s → lost · clocks frozen60 s grace → adjourned · saved

Host drops. The friend sees "Host connection lost, reconnecting… 0:52". Chessfish retries with backoff (0.5 s, 1 s, 2 s and so on, capped at 10 s). It then sends a new handshake plus RESUME with the session's resume token, and the exact position and clocks come back.

Friend drops. The game holds and the same grace rules apply. You see "Friend disconnected" with the timer.

Grace runs out. The game is adjourned and saved to SQLite, and you can resume it later from the GUI.

Who sees what

Friend · browser on :6767

A clean online-chess page

  • Enters a display name, then sees "Waiting for game" until a countdown starts the game
  • The other side is always shown as "Opponent"
  • Board with drag or click moves, legal-move dots, last-move and check highlights
  • Promotion picker and board flip
  • Sounds for move, capture, check, castle, game start/end and low time
  • Move list in SAN and both clocks
  • Resign, plus offer or accept a draw
  • Chat
  • Ping badge and banners: waiting, reconnecting, adjourned
  • No evals, best moves, settings or rematch buttons, and nothing that says engine or human
You · Chessfish on the gaming PC

Everything, in a multithreaded GUI

  • Settings: server IP/port, pairing key, Stockfish path, Threads, Hash, MultiPV
  • Session control: start, pause, adjourn, abort, resume an adjourned game
  • The live board, where you play in human mode
  • All statistics (below), plus link health for both legs
  • Optional browser dashboard on the same PC

Threads: UI · engine · link · stats · dashboard. They talk through Qt signals, so analysis never freezes the window.

The statistics

Stockfish streams these while it searches, and Chessfish derives the rest after every move.

Engine, live

  • Eval in centipawns or mate-in-N
  • Win / draw / loss %
  • Depth and seldepth
  • Nodes, NPS, hash fill, tablebase hits
  • Principal variation for every MultiPV line

Probable moves

  • Top-N candidates for both sides
  • Probability spread across the candidates
  • Predicted reply from the friend
  • Eval swing per candidate
  • Threats if the side to move passes

Game

  • Eval graph over the game
  • Centipawn loss and accuracy % per player
  • Move grades: best, excellent, good, inaccuracy, mistake, blunder
  • Opening (ECO code and name) and game phase
  • Material, mobility, hanging pieces, king safety

Time and network

  • Think time per move and clock usage curves
  • RTT, jitter and loss for both legs
  • Link state history and reconnect log
  • Packet counters and session info

Engine or human? The friend can't tell

The friend's page gets exactly the same messages in both modes, and no engine name or mode ever reaches it. Stockfish waits a human-like amount of time before each move, scaled by the clock, the increment, the move number and how complicated the position is. Forced moves and recaptures come quicker. Strength is capped by the Elo setting, and chat reaches you in both modes.

The installer

The gaming-PC side is a single ChessfishSetup.exe you can hand to another machine. Nothing needs to be installed there first: Python and Stockfish come inside it.

By default it installs into the folder you run it from. You can pick another location, and choose between installing just for you (no admin prompt) or for all users. Settings, logs and saved games stay inside the install folder.

It needs no firewall rules, because Chessfish only connects out. Your Tailscale setup stays exactly as it is. The link port is protected by the pairing-key handshake, so anything without the key is dropped before it sees a game.

First-run wizard
  1. StockfishDetects CPU features (AVX-512, BMI2, AVX2…), picks the matching bundled build and runs bench to prove it works.
  2. HardwareDetects cores and RAM, then suggests Threads = cores − 1 and Hash = 25% of RAM (up to 4 GB).
  3. ServerEnter the container address and port 6768, then use Test connection to see the handshake and RTT.
  4. Pairing keyGenerate one or paste an existing one. It is stored with Windows DPAPI.
  5. Docker filesWrites a ready docker-compose.yml and an .env with the key filled in. Copy both to the VM and run docker compose up -d.

Stockfish only plays and analyses. It does not enforce the rules of chess; python-chess does that on the server.

Build order

  1. Protocol and cryptoHandshake, sealed frames and replay guard, all with unit tests.
  2. Server coreGame state, clocks, friend socket, host link and storage, tested against a fake host.
  3. Friend websiteBoard, dots, sounds, move list, clocks, chat and status banners.
  4. Link clientConnect, heartbeat, reconnect and resume, first as a command-line harness.
  5. Chessfish GUISettings, session control, board, and the engine worker for both modes.
  6. StatisticsEvery metric above, with graphs.
  7. Local web dashboard
  8. InstallerThe PyInstaller build, the Inno Setup script and the first-run wizard.
  9. Deploy and testRun docker compose up -d on the VM and install on the gaming PC. Then test end to end, including pulling the network cable mid-game.

Settled

  • Ports: 6767 for the friend site, 6768 for the link.
  • Tailscale settings are never touched.
  • The friend enters a display name and only ever sees "Opponent".
  • No rematch buttons. The friend waits, then gets a 10-second countdown.
  • Games are saved as PGNs on the gaming PC only.
  • The installer covers the gaming PC and writes the Docker files.
  • Install location defaults to where the setup runs, and can be changed, per user or for all users.
